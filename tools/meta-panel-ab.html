What changed in v1.12.0. Every control on this page carries margin-bottom: 15px from a global rule that predates the grid, and inside a grid cell that margin is inside the cell — so a control's visible bottom sat 15px above its own cell's bottom while the cover frame filled its cell exactly. That one 15px is why the cover column would not line up with the rows to its left. The gap is the only vertical spacing now.

The cover's file input and Remove sit side by side, one row tall. Stacked, they forced the last field row to grow and Prepared by / Cleaned up by stopped lining up with everything above. The column went 160px → 200px to fit them.

What changed since v1.10.0, and why. v1.10.0 gridded the fields and left the title row on flex, so Save Metadata lined up with nothing underneath it. The header row and the field grid now share one grid-template-columns declaration — two things meant to agree and declared separately will disagree the first time one is edited.

Save Metadata's alignment is a spacer label. Its cell has no label of its own, so the button used to start at the top of the cell while the inputs beside it started below their labels. The spacer is visibility:hidden, not display:none — the latter reserves no height and the alignment silently reverts.

The cover is a slot of three rows now, not an image of whatever height the jacket happens to be. Its top and bottom are gridlines, and its file input and Remove sit on the last field row beside Prepared by / Cleaned up by. The column went 120px → 160px, so the picture is larger as well as aligned.

Uploaded by now says when it fills in. It is stamped on first upload from the signed-in account and never by Save Metadata, so a book you are staging has no stamp — a bare em dash read as broken rather than as "not yet". It is still read-only. The dropdown of admins and teachers is ROADMAP 55b and needs your ruling on who may set it.

What did NOT change. Every id, every option value, every handler. No colour moved.
