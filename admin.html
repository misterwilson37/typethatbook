📋 How-to: the quarterly routine, deletion requests, and sign-in accounts (click to open)

Every quarter (about 10 minutes)

  1. Retention check — section 3 below. Press Check. It lists anyone with no saved score in 24 months and tells you who is next to expire, and when. If nobody is listed and the next date is months away, you can skip checks until then.
  2. If anyone is listed, type the confirmation it asks for and press Expire these students. Their initials and scores stay on the boards; their email record is deleted.
  3. Sign-in accounts — web pages aren't allowed to delete them, so do it in Google Cloud Shell (below).
  4. Picture sources — section 4 below. Press List picture sources. Everything should be green; if not, press Move outside pictures into SpotOn.

Opening Google Cloud Shell

  1. Go to console.cloud.google.com and sign in as yourself.
  2. At the top of the page, make sure the project says spot-on-games (click it to switch).
  3. Click the >_ button at the top right (Activate Cloud Shell). A terminal opens at the bottom of the page. Paste commands into it with ⌘V and press Return.

First time only (or if it has been a long time and something errors)

pip install --user --quiet firebase-admin
gcloud auth application-default login --no-launch-browser

This prints a long link. Open it, sign in as yourself, allow access, copy the code it shows, paste it back into Cloud Shell, press Return.

gcloud auth application-default set-quota-project spot-on-games

Every time

curl -sO https://spoton.misterwilson.org/scripts/auth-cleanup.py

Downloads the current script from the live site.

python3 auth-cleanup.py

Only lists: accounts unused 24+ months, and the next one due. Changes nothing.

python3 auth-cleanup.py --delete

Deletes them. It asks you to type delete plus the count (e.g. delete 5) first; anything else cancels. Your two admin accounts are never deleted. "Unused" counts a browser quietly staying signed in, so students who stay signed in on their MacBook aren't deleted.

A parent or the school asks to delete a student

  1. Section 2 below: enter the email, Find, type the email again, Delete this student.
  2. Then in Cloud Shell (after the "Every time" download), replacing STUDENT_EMAIL with their email:
python3 auth-cleanup.py --email STUDENT_EMAIL --delete

Must be done within 30 days of the request (the policy promises it). Confirm the request through the school first.

A family asks that nothing more be collected

python3 auth-cleanup.py --email STUDENT_EMAIL --disable

They can still play the games, but can't sign in, so nothing is ever saved. (Delete their existing records with section 2 if they asked for that too.)

Just look up one account

python3 auth-cleanup.py --email STUDENT_EMAIL

If something goes wrong

  • An error mentioning "quota project" → run the set-quota-project command above, then try again.
  • An error mentioning "credentials" → run the application-default login command above, then try again.
  • "No module named firebase_admin" → run the pip install command above.
  • Anything else → copy the whole Cloud Shell output into a new Claude chat along with the SpotOn repo.

One-time setup: let the games read pictures from storage (CORS)

Sweet Spot's cropped pictures, and this page's Sweet Spot level editor, read picture pixels, and the storage bucket must allow that for spoton.misterwilson.org. Done once; do it again only if pictures start failing with a "CORS" error in the browser console. Run in Cloud Shell:

echo '[{"origin":["https://spoton.misterwilson.org"],"method":["GET"],"maxAgeSeconds":3600}]' > cors.json
gcloud storage buckets update gs://spot-on-games.firebasestorage.app --cors-file=cors.json
gcloud storage buckets describe gs://spot-on-games.firebasestorage.app --format="default(cors_config)"

The last one should print the spoton.misterwilson.org origin back. Browsers can remember the old answer for up to an hour.

The Cloud Shell sign-in account steps also live at the top of scripts/auth-cleanup.py in the repo.

1. Legacy cleanup (one time)

Before September 2026, most games put each student's email, Google name and profile photo on their public score records. This moves every email into the private player records (only admins can read those) and then strips email, name and photo off every score. Initials and scores don't change. Safe to run again.

2. Delete a student (on a school or parent request)

Deletes the student's scores and their email record. Nothing is deleted until you've seen the count and typed the email again.

3. Retention check (once a quarter)

Finds students who haven't saved a score in 24 months. For each one, their email record is deleted and their scores become anonymous — the initials and scores stay on the leaderboards, attached to no one.

4. Where the game pictures load from

Every website listed here sees a student's IP address when a game shows its picture. Firebase Storage (firebasestorage.googleapis.com) is Google, which already runs SpotOn's database; anything else is another company. Move copies every outside picture into SpotOn's own storage and points the game at the copy (the original address is kept as a credit, never loaded).
